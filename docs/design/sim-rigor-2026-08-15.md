## 1. Stream splitting, tested rather than asserted

### 1.1 The property is structural at the derivation layer

`packages/sim-core/src/rng/source.ts` builds `RngSource` as *"a seed plus two derivations"* that
*"holds no draw position and no mutable state of its own"*. Every `stream()` / `actorStream()` call
returns a **fresh cursor** derived purely from `(rootSeed, subsystemId, tick[, actorKey])`.
Insertion invariance therefore cannot fail in the mixer. It can only fail at a **call site**: by
borrowing another subsystem's id, or by threading one cursor object through two subsystems' logic.

`rng-registry-append-only.test.ts` does not test either of those. It pins table shape and locks the
table to `contracts.md` §6 — detection of a *renumbering*, not of a *coupling*. This section is the
missing half.

### 1.2 The probe

The instrument is an uncommitted patch to `packages/sim-core/src/rng/source.ts` (tag every derived
cursor with its coordinates, and record the derivation) and `packages/sim-core/src/rng/pcg32.ts`
(record `coords=value` for every `nextUint32`). A probe test drives `runLongReference({ ticks: 240 })`
— the reference universe, 20 world years, no player actions — and dumps the log. Three variants of
one call site in `packages/rules-world/src/mages/mortality.ts`:

- **`base`** — unmodified.
- **`newstream`** — one extra draw per mage per tick on a *new* stream id 13, **result discarded**.
  Nothing about the world changes, so any difference in streams 1–12 is a coupling and nothing else.
  This is the exact shape of what #170, #185 and #186 each add.
- **`sharedcursor`** (positive control) — one extra draw per mage per tick taken from mortality's
  **own cursor object**. Note precisely what this validates: it shifts mortality's *own* sequence,
  so it proves the instrument can see a displaced cursor at all. It is not a replica of the
  cross-subsystem case (a corruption draw taking from scribing's cursor); it is the detection
  mechanism that case would have to trip. The load-bearing result is `newstream`'s identical hash,
  which stands on its own.

Instrumentation coverage was checked before the comparison: **0 of 32,554 draws were untagged**, so
no draw escaped the log.

### 1.3 Result

| Variant | draws on ids 1–12 | SHA-256 of that log (first 32 hex) |
| --- | --- | --- |
| `base` | 32,554 | `ca24b60b9a20bacab36e0f5a0654020e` |

The positive control diverges at **draw 38** — stream 2, tick 0 — and inserts 13,977 extra draws
into stream 2. The probe is not blind: it detects the coupling it was built to detect, immediately.

## 2. Actor-keying

### 2.1 The three new draws

| PR | Stream | Call site | Key | Cardinality |
| --- | --- | --- | --- | --- |
| #170 | `corruption` | `rules-magic/src/instances/scribing.ts` | `inputs.scribe` — mage handle | 1 per scribing act |
| #170 | `corruption` | `rules-raid/src/consequences.ts` | `packCombatantKey(saboteur.key)` | 1 per sabotage |
| #185 | `career` | `rules-world/src/mages/careers.ts` | `mage` — mage handle | 1 per graduate |
| #186 | `detachment` | `rules-raid/src/portal.ts` | `cohort.handle` | 1 per eligible cohort |

All four are stable entity identities, not positions. All four take the draw **unconditionally** —
before the value is compared, and whether or not the branch fires — which is what keeps the draw
*count* from depending on the data. #170 and #186 both argue this in the source; #186's comment is
the clearest statement of the rule in the repository.

Two deliberate departures, both sound:

- **#186 passes `side` as the `tick` argument.** Deployment happens outside any world tick, and the
  two participants are separate worlds with independently numbered handles, so without it attacker
  cohort 7 and defender cohort 7 would draw the same value. It follows the pre-existing raid-side
  convention (`raid.ts:312` uses `1`, `objectives.ts:251` and `terrain.ts:107` use `0`). Consequence
  worth knowing, and it is a **static read** — no probe here exercises it (§1.4): the same cohort
  deploying on the same side in two different raids draws the same value, since neither the world
  tick nor a raid id is in the coordinates. That is deterministic and correct, but it is a repeat,
  not a fresh roll.
- **#185's `career` is one draw per *person*, where `promotion.ts` is one draw per *cohort*.** The
  source argues it: a per-cohort draw would give every graduate in a tick the same career, and a
  positional key would re-roll every graduate's career when one more graduates. Both are right.

### 2.2 Is any new draw `O(people)`?

**No.** Measured per-tick counts from §1.3:

- `corruption` shares `scribing`'s cardinality: 633 draws over 240 ticks, ~2–3 per tick. `O(scribing acts)`.
- `career` is `O(graduates per tick)`, bounded by university seats, not by population.
- `detachment` is `O(eligible cohorts)` — explicitly `O(cohorts)`, not `O(people)`.

**What is already `O(people)`, on `main`, before any of these PRs:** `killTheDead` in
`coordination/src/world-step.ts` iterates every live `MAGE` row and takes one `mortality` draw for
each, with no role filter. Measured: **6 draws at tick 0, 57 at tick 239** — one per living mage per
tick. `populace` behaves the same way per cohort (30 → 60).

**#181's second-order effect is the one to watch.** Students become `MAGE` entities in a `student`
role; #181's own report field comment says *"`livingMages - studentMages` is the old quantity"*, so
students are live mage rows, and `killTheDead` gains no student filter. Every enrolled student
therefore takes a mortality draw every tick. That is not a determinism defect — students are people
and should be mortal — but it multiplies the one draw site that already scales with population, and
replay cost scales with it. It is worth a measurement after #181 lands, not a change now.

### 2.3 Pre-existing positional actor keys (static read, `main`)

`deriveActorStream`'s own contract says the key *"must be a stable identity — an entity handle —
never an array index, a roster position, a loop counter"*. Three raid-side call sites on `main`
violate it:

- `rules-raid/src/consequences.ts:252` — `actorStream(RNG_STREAM.scribing, worldTick, ordinal)`,
  where `ordinal` is the index of `shelved.forEach`. One grimoire added to or removed from a shelf
  ahead of another re-rolls whether the later book burns.
- `rules-raid/src/terrain.ts:107` — `actorStream(RNG_STREAM.terrain, 0, index)`, a loop index.
- `rules-raid/src/objectives.ts:251` — `actorStream(RNG_STREAM.objectives, 0, ordinal)`.

None is introduced by an open PR, and none is exercised by any probe here (see §1.4). Recorded so
the next raid-side change does not copy the pattern.

## 3. Float and clock leakage

### 3.1 What `check:purity` actually checks

`npm run check:purity` passes at `3b90089c`. It reads **`package.json` manifests only** — it asserts
that eight packages declare no third-party runtime dependency and carry the AGPL license string. It
never opens a source file. It cannot see a float, a `Date.now()`, or a `Math.random()`, and it does
not claim to.

**Non-negotiable 2 holds**, and that is all `check:purity` establishes.

### 3.2 What enforces the float and clock ban, and where it stops

The ban lives in `eslint.config.mjs`, scoped to four globs: `CORE_SRC` (`sim-core/src`,
`sim-core/bench`), `RULES_SRC` (`state`, `rules-magic`, `rules-world`, `rules-raid` — `src` only),
`PRIMITIVES_SRC`, and `agent-api` under a documented one-file exemption.

**`packages/coordination/src` and `packages/scenario/src` are in none of them.**

Positive control — the identical line appended to three files, then `npx eslint` on all three:

```
const __PROBE_FLOAT = 0.5 + Date.now() + Math.random() + Math.sqrt(2);
```

| File | eslint result |
| --- | --- |
| `packages/rules-world/src/mages/mortality.ts` | **5 errors**: decimal literal, `Date`, floating-point `Math` ×2, `Math.random` |
| `packages/coordination/src/world-step.ts` | **0 errors** |
| `packages/scenario/src/reference-universe.ts` | **0 errors** |

`scripts/check-purity.mjs` names `coordination` as rules path in as many words — *"The rules path in
full, not just the core… `state`, the three `rules-*` packages and `coordination` are loaded by the
client, the server, and the Monte Carlo workers alike"*. eslint's `RULES_SRC` omits it. **Two tools
in this repository disagree about what the rules path is, and the one that carries the float and
clock ban is the one with the narrower answer.**

One further gap in both tools: the `/` operator is not banned anywhere in the rules path. Integer
division through `floorDiv` is convention and review, not enforcement. (`agent-api` bans `/` by a
dedicated test, `float-boundary.test.ts`; the rules packages have no equivalent.)

### 3.3 Does anything catch it at runtime?

Two injections into `coordination/src/world-step.ts`, both with lint passing:

**(a) Into `countLivingMages`** — `if (Math.random() < 0.5) count += 1;`. The line executed **7,532
times** (verified by an instrumented print). Result: `npm run lint` clean, **335 test files and
4,631 tests all passed**, `vitest exit=0`. Its value lands in the world report's `livingMages`,
which is read by `coordination/src/god/ascension.ts` and `scenario/src/measures.ts` — not a pure
diagnostic — but it is not in the hashed snapshot, and in a run that submits no god actions its
consumers never fire.

**(b) Into `deliverBirths`** — `if (Math.random() < 0.5) continue;`, which changes state. Caught:
**8 test failures across 5 files**, led by
`coordination/test/unit/world-step.test.ts > the loop is deterministic > produces the same snapshot
hash at every tick across two runs` and
`scenario/test/unit/reference-long-run.test.ts > 9.6 — produces a byte-identical final snapshot hash
across two executions`.

So the honest statement of **non-negotiable 1**: nondeterminism in `coordination/src` that reaches
**state** is caught by two snapshot-hash tests. Nondeterminism that reaches only a **report field**
is caught by nothing — not lint, not `check:purity`, not 4,631 tests. And no tool stops it being
written in the first place.

### 3.4 The in-flight code is clean

Every `Math.*` member added by the nine PRs across `packages/**/src` is on the integer-safe
allowlist (`abs`, `min`, `max`, `sign`, `imul`, `clz32`). Added decimal literals appear only in test
files, where they are permitted. The three places the brief flagged as float-shaped are all
fixed-point integer arithmetic:

- #170's fidelity curve — `generationStep` / `scribalErrorChance`, both `Math.min`/`Math.max` clamps
  over `floorDiv` results.
- #185's career probability — `schoolingNudge`, clamped between `ACADEMIC_CHANCE_FLOOR` and
  `ACADEMIC_CHANCE_CEILING`, compared against `nextBounded(…, FP_ONE)`.
- #183's mastery ceiling — `Math.min(MASTERY_MAX, base + perTier * headroom)`.

The only `Math.floor` anywhere in the diffs is in a `rules-raid` **test** file (`Math.floor` is *not*
on the allowlist, so it would fail lint in `src`). The rules-path `src` on `main` contains no
`Math.floor`, `Math.trunc` or `Math.round` at all.

### 3.5 The macro model stays outside

`tools/w189/` is float by design and **confirmed outside the rules path**: it imports nothing from
`@mm/*` (its only imports are `node:fs`, `node:url`, `node:path`, and its own three modules), it
carries its own float PRNG `mulberry32`, and `git grep w189 -- packages scripts balance` returns
nothing. Not a violation. Do not report it as one.

- **2 shared helpers** do too (`raid-fixture.ts`, `warband.ts`), pulling in `combat-knowledge`,
  `grimoire-durability`, and — outside the package — `content/test/unit/interning.test.ts` and

- **And the `src` of four aliased packages** import it: `rules-magic/src/effects/consumption.ts`,

this is masked because `npm run verify` runs `typecheck` first and `dist` is therefore fresh. It is

probe written against that source — which is why §1.4 restricts this pass's raid claims to static

| # | Constraint | Holds? |
| --- | --- | --- |
| 1 | Deterministic core; no float, no clock in the rules path | **Partly.** No violation exists in `main` or any open PR — but the ban is *unenforced* in `packages/coordination/src` and `packages/scenario/src`, and the runtime net has a hole (§3.2–3.3). |

| 4 | Goldens regenerated only by explicit command | **Yes**, verified by execution and by reading the guard (§5). |

Answers to the specific questions asked:

- **Are the new streams genuinely independent?** Yes. 13,521 draws added on a new id left all 32,554
  draws on ids 1–12 bit-identical; the shared-cursor control diverged at draw 38.
- **Any `O(people)` draw?** None added. `mortality` is already one draw per living mage per tick on
  `main` (6 → 57 over 240 ticks); #181 grows the mage population with students and so grows that
  count, without adding a draw site.
- **Any schema-revision collision among the open PRs?** Yes, two: three PRs at `RNG_STREAM` id 13,
  and #170 and #171 both at world-schema revision 7. Both conflict loudly at merge; §4.4 states the
  four-step reconciliation the second merge needs.
- **Any package still missing from the alias table?** One: `@mm/rules-raid`, fixed only by #186.

### The single most dangerous thing found

**`packages/coordination/src` — the world loop — sits outside eslint's rules-path glob, so
`Math.random()`, `Date.now()` and float literals are legal there and nothing says a word.** The
repository's other purity tool names `coordination` as rules path in its own comments; the tool that
carries the ban does not.

The reason this outranks the two merge collisions is that the collisions are *noisy* — every one of
them produces a git conflict a human must resolve — while this one is silent in both directions.
`Math.random()` inside `world-step.ts` passed `npm run lint`, executed 7,532 times, and passed all
4,631 tests. It is caught only if the perturbed value reaches the hashed snapshot; a report field
alone is not enough. The fix is one line — add `packages/coordination/src/**/*.ts` to `RULES_SRC` —
but this pass is a check, not a repair, and the change belongs on a branch that can run the full
suite behind it.

## 9. Addendum, 2026-08-15: what the fix exposed

Written after §3.2's gap was closed by **PR #190**, branched from `origin/main` at
`08ca53684a5f29b24be0bffea615f760faacc400`. This section is a finding the audit could not have had,
because it only becomes visible once the glob is applied.

Adding `packages/coordination/src/**/*.ts` to `RULES_SRC` raised **four float divisions** in the god
layer that no tool in this repository had ever seen:

| Site at `08ca5368` | Was |
| --- | --- |
| `coordination/src/god/ascension.ts:522` | `Math.floor(share(…) / FP_ONE)` |
| `coordination/src/god/ascension.ts:523` | `Math.floor((nodes * FP_ONE * budget) / (FP_ONE * FP_ONE))` |
| `coordination/src/god/interventions.ts:443` | `Math.floor((cellId - 1) / GRID_FORM_COUNT)` |
| `coordination/src/god/interventions.ts:846` | `Math.ceil(encourageMagnitude / encourageDecayPerTick)` |

**The sharpest of the four is the first pair.** `ascension.ts` states the rule at line 228 —
*"Integer arithmetic throughout: `floorDiv` over fixed point at 1/1024, never a…"* — imports
`floorDiv`, uses it at lines 228, 270 and 423, and then divides with `/` at line 522 in the same
file. `state/src/god.ts:152` and `state/src/grid.ts:68` carry the same note over the same arithmetic
and use `floorDiv`, because they were linted. That is the whole cost of the missing glob in one
file: not that nobody knew the rule, but that nothing checked it.

This is not stylistic. Float division of two integers rounds the quotient to a double before the
floor, so a true quotient just under an integer can round up across it — which is why the ban exists.

All four are `floorDiv` in #190, the ceiling written as the exact integer identity
`floorDiv(a + b - 1, b)`. An equivalence sweep over every reachable input — all 70 cell ids, every
`(magnitude, decay)` pair over `0…8192 × {1,2,3,4,5,8,16,64,256}`, and the full budget range for both
legacy grants — found **0 disagreements in 82,001 comparisons**, so no shipped behaviour moves.

Two further things the fix established that §3.2 did not know:

- **`scenario` is a documented exclusion, not an oversight.** Its nine float sites are all statistics
  and reporting — `species-separation.ts` computes standard deviations and standard errors,
  `census.ts` and `measures.ts` report — and none is in the state it seeds. It is also a genuine
  leaf: the four `@mm/scenario` mentions in other packages' sources are prose in comments.
- **`server` and `gym-bridge` were unmentioned by the comment too** — the same silence that hid
  `coordination`. Six exclusions, seven rules-path packages, thirteen packages, and
  `purity-lint.test.ts` now reads `packages/` off disk and asserts that partition, so a package added
  without being classified fails the suite.
