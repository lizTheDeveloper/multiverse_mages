Tempo, and what is allowed to interrupt

Two of electron-client's open questions are one question. The client owns a wall-clock pacing that nobody has chosen, and speed decides what an event is — at 4× a world tick is a fraction of a second. sound-design §0.4 already answers the audio half: below a per-class threshold events play discretely, at or above it the class becomes a texture whose intensity tracks the rate. Four scribes are four pens; four hundred are weather. This applies the same rule to the eye.

All three run off one simulated stream. Change the population — the routine classes cross their thresholds and turn to texture, while loss stays discrete at any scale.

What operating these settles

The density rule transfers, and it is the whole answer to the feed. Research, teaching and scribing all cross their thresholds somewhere between 200 and 600 mages and stop being readable as lines. Turning them into a rate bar is not a compromise — it is more information than a scrolling list, because a bar shows the trend and a list shows only the last five things. Loss never crosses a threshold, because it is rare by construction and must never be averaged.

A is the honest default and it fails the game's own thesis. Speed controls plus a feed is what every management game ships, and it makes attention the player's problem. Vision §5 says the emotional core is a loss that happens silently. A player at 4× who is looking at the ruleset will miss it, every time, and the interface will have been technically correct.

B is the one that matches the design and it costs a decision. If the world halts itself when the last copy of a node dies, the game has asserted that this is the most important thing that can happen — which is exactly what vision §5 claims. But an auto-halt is an interruption the player did not ask for, and sound-design §0.3's salience-parity rule is satisfied by either a halt or a loud visual. Halting is the stronger claim and the more annoying one; that trade is a playtest question, and it is cheap to try because the mechanism is the same either way.

C is not a joke. Removing speed control entirely and advancing by reading makes the feed the clock, which suits a game with no map and no units to command. It also makes the tempo-lost-to-inbound- raids metric (vision §8) meaningless, because there is no wall clock to lose. Worth knowing before anyone specifies that metric against a client that may not have a clock.

The interruption policy is downstream of concentration, and that is now measured. Drag the loss slider: under about one last copy a year the halt is the best moment in the game, past roughly three a year it is a nuisance. W8 settled which end reality sits at, and it is neither — nodesLost is 0.00 for six of eight strategies and libraryDependence is 0, so the halt never fires at all. Raids burn books and remove nothing, because at 50–80 copies per node every library is held fifty other places. The choice between halting and a conventional feed therefore cannot be made by playing, and it is blocked on concentration rather than on a decay rate — which is not a number this screen or any tuning pass can move.

One threshold per class, read by both layers. These numbers are the same numbers the audio uses rather than a visual set that happens to look similar. Two layers choosing independently would disagree about the moment a class became weather, and a player would see discrete events while hearing a texture — worse than either layer being wrong alone, because it is the interface contradicting itself. sound-design §0.4 now states this as a rule.

Loss does not scale with population, and modelling it that way was my first mistake here. More mages means more deaths but also more copies. Every other class in this prototype scales with headcount; loss gets its own control, because how often a last copy dies is a property of redundancy rather than of how many people there are.

Prototype · not the client. The event stream is generated from a seeded PRNG at plausible rates, not sampled from a real run; contracts §0 keeps real-time pacing out of the core entirely.
